# Xbox One / Series (UWP, Dev Mode): packaging, host, and the device-removal history

> **Purpose:** how the Xbox UWP host is built and packaged, how it is configured on the console, and what the nine console runs taught · **Status:** current (2026-10-26; the port is paused) · **Tags:** [Xbox] (console facts); the rest is host platform

**Paused** (user decision 2026-10-23; the priority is the desktop). The game ran on a Series X at **15-21 fps,
CPU-bound** (packages 1.0.2488.849/.900). Code: `runtime/host/uwp/`, `cmake/toolchains/uwp-x64-llvm-mingw.cmake`,
`tools/xbox/` (full guide: [`tools/xbox/README.md`](../../../tools/xbox/README.md)). The backend details are in

## The app
A **UWP** app (CoreApplication view) running the same runtime as the desktop with its own host (`runtime/host/uwp/`): a D3D12 swap chain on the CoreWindow (plume `PLUME_D3D12_COREWINDOW`), gamepad through Windows.Gaming.Input, sound through XAudio2 2.9 (`host/audio_xaudio2.cpp`), a **small SDL subset** (`sdl_subset.cpp`: SDL3 has no UWP; its headers `#error` under `WINAPI_FAMILY_APP`; RGBA32 surfaces, `SDL_LoadPNG`/`SavePNG` via stb, `SDL_RenamePath`, `SDL_GetWindowSize`, no-op text input), raw WinRT ABI through mingw-w64 headers (no C++/WinRT, no Windows SDK). The disc image is read from the package (`game.iso`, ~8.7 GB, **stored uncompressed**); saves, figures and the log (`LocalState\Arkeyan.log`) are in LocalState. `check_uwp_imports.sh` must print OK: all 234 imports in windowsapp/ucrtapp (libc++'s `GetActiveProcessorCount` import replaced; the translated code's `_setjmp` redirected to ucrtapp's own). **Gamepad B must be handled** (`BackRequested`) or the app is sent Home.
One x64 package serves Xbox One (Jaguar: AVX, F16C, BMI1; no AVX2/FMA/BMI2) and Series: `-march=btver2`. **Series-only** `-DARKEYAN_UWP_MARCH=x86-64-v3` (AVX2/FMA/BMI2, `-ffp-contract=off` so the guest's floating-point results stay those of separate multiplies and adds): `host/uwp/cpu_check.cpp` runs as the first static constructor and, without them (an Xbox One), writes the reason to the log and exits.

## Build and package
```
tools/xbox/setup_tools.sh                          # private/xbox: llvm-mingw, makemsix (patched), osslsigncode (adapted for >4 GB), ~1.5 GB
tools/prepare_game.sh "<iso>"
cmake -S . -B build-uwp -G Ninja -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/uwp-x64-llvm-mingw.cmake -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_C_FLAGS_RELEASE="-O2 -DNDEBUG" -DCMAKE_CXX_FLAGS_RELEASE="-O2 -DNDEBUG"        # optionally -DARKEYAN_PPC_LIBRARY=<win64 lib>
ninja -C build-uwp -j4 ArkeyanRuntime ; tools/xbox/check_uwp_imports.sh "build-uwp/ArkeyanRuntime/Skylanders Spyro's Adventure.exe"
tools/xbox/package.sh --exe "build-uwp/ArkeyanRuntime/Skylanders Spyro's Adventure.exe" --iso "<iso>" --out SSARecomp.msix    # --no-iso: small test package
```
- `package.sh` creates a per-user self-signed certificate (`CN=SSARecomp Local`, in `<application data>/SSARecomp/xbox-signing`; keep it: packages signed with it install over each other), bumps the version automatically (`--version a.b.c.d` forces one), prints the **family name** `SSARecomp.SpyrosAdventure_<id>`. App type **Game** must be set in Dev Home (else the small "App" budget). Disk: **~18 GB free** while packaging (unpacked + signed together; the ISO is hard-linked when on the same disk).
- **makemsix** deflates by extension and `.iso` is not in its store list: `tools/xbox/patches/makemsix-store-iso.patch`; **bundles are not implemented** (`AddPayloadPackage`); packages **> 4 GB need zip64** the way MakeAppx writes it: only the values that overflow move into the zip64 extra field (the image's two sizes; the offset alone for later files), local headers without extra field and a 24-byte data descriptor; osslsigncode 2.14 had to be fixed to keep that minimal form (version needed 4.5) for the appended `AppxSignature.p7x`. The package that failed with `0x8007000B` had all three values in every zip64 field.
- Install: Device Portal (`https://<console-ip>:11443`, upload ~8.8 GB) or "Register from network share" with a **loose folder** (updating = copy the new `SSARecomp.exe` over the registered one).
- `AppxManifest.xml.in`: capabilities incl. `humaninterfacedevice`, publisher cache folder `Skylanders` (shared collection), `broadFileSystemAccess` for a user-chosen ISO (`CreateFile2FromAppW`). All Skylanders apps of the same publisher must use the same `Publisher` and folder name.

## Console settings (`LocalState\launcher.ini`, written at first start)
`resolution_scale` 2 on Series, 1 on One (`AnalyticsInfo.DeviceForm`); glyphs `xboxone`; `[portal] mode` auto/real/emulated; `[gpu]` safe-mode keys: `thread=off` (default; `on` = GPU thread), `pipeline_library=off` (default on UWP). The first 40 D3D12 steps are logged `[gpu] step N: <what> (thread T)` (device, queue, present pipelines, swap chain, worker, command lists executed, presents, shader cache, pipeline library), with "device REMOVED" after a removal: **the first such line names the culprit**.
Log lines to look for in `Arkeyan.log`: `[gpu] D3D12 on ...`, `[gpu] shader cache: 1118 shaders`, `[gpu] first present WxH`, `[uwp] view activated (kind N)`, `[uwp] window visible/hidden`, `[gpu] presents: N in the last 5 s (last from thread X)`, no `CreateGraphicsPipelineState failed`, no `Fault`, `[perf]` every 10 s.

## The device-removal and presentation history (9 console runs; avoid repeating it)

| Run (package) | Symptom | Cause | Fix |
|---|---|---|---|
| first boot (10/23 20h35) | crash when the intro movie starts | a game draw on D3D12 with a pipeline built from SPIR-V | D3D12 skipped draws until DXIL existed; then **one DXIL per specialization, signed** ([shaders.md](../../runtime/gpu/shaders.md)) |
| run 2 (1108) | splash screen forever; `CreateResource` fails with `DXGI_ERROR_DEVICE_REMOVED` at the frontend load | render and depth targets were **placed** resources (plume's generic desc): they must be cleared/discarded/copied before any other use; the resolves and copies read EDRAM targets that skipped draws never wrote: garbage compression metadata, a classic AMD GPU fault (found with the Vulkan validation layer under vkd3d-proton: `VUID-vkCmdDraw-None-09600`, a depth target read in layout UNDEFINED) | **committed** targets (D3D12 initialises them); DRED on before device creation, `GetDeviceRemovedReason` checked after every frame (reason, last operations of unfinished command lists `->`, page fault address with allocations, video memory), splash replaced by presenting a black frame right after `Activate()` |
| run 3 (1236) | first present OK (1920x1080), then removal at the frontend load; crash in `UploadTexture` (failed `Map` returned null) | `gpu::ResolveDepth` bound the depth target with `setTexture` and **no view**: plume creates D32S8 targets as `R32G8X24_TYPELESS` and `CreateShaderResourceView(resource, nullptr)` is invalid on typeless resources | plume gives a typeless depth texture its depth plane's format (`R32_FLOAT_X8X24_TYPELESS`); block-compressed mips < 4x4 round their footprint up to whole blocks; any failed creation/pipeline/null `map()` checks the removal at once; memory log per texture >= 16 MB |
| run 4 (1270) | no D3D12 error, `first present 1920x1080`, movies play, **the splash stays**, the Xbox guide stays frozen | the CoreWindow was never the activated, composed view | activate as Microsoft's CoreApplication/DirectX template: subscribe to `Activated`, its handler calls `CoreWindow::Activate()`, `Run` pumps `ProcessEvents` until it came (5 s max) **before** the disc, XEX and guest threads; swap chain `DXGI_SCALING_STRETCH`, `DXGI_ALPHA_MODE_IGNORE` |
| present test 1 | the raw D3D12 template (GREY) showed; plume's path (RED) presented without errors and **was never shown** | plume's swap chain flags (FRAME_LATENCY_WAITABLE_OBJECT, ALLOW_TEARING, `ResizeBuffers`) differ from the template's | CoreWindow swap chain exactly as the template (flags 0, `Present(1, 0)`, no resize, FLIP_DISCARD, 2 buffers, B8G8R8A8); **Presents issued from the UI thread** (`gpu::ServicePresents`: the game thread records and submits, hands the Present to the UI thread and waits <= 200 ms, then presents itself); a separate small "present test" package (`tools/xbox/presenttest`) checks flags one by one |
| run 6 (555) | **the game shows**; 4 fps in the level, 19 s of pipeline builds | no persistent pipeline cache; per-draw rebinding | `ID3D12PipelineLibrary` (`pipelines.d3d12`), `[perf]` log every 10 s |
| run 7 (769, GPU thread) | DEVICE_REMOVED (`DRIVER_INTERNAL_ERROR`, every command list completed, no page fault) at start, between device creation and the shader cache load | the GPU-thread model on the console; the UI thread can block on the GPU thread while it waits for the UI thread to Present (falls back after 200 ms: unshown Presents) | `thread=off` by default on the console; `WaitServicingPresents` / `ProducerLock` service the Present handoff while waiting; the UI thread registered as the present thread from the swap chain on |
| run 8 (831) | `step 6: pipeline library opened - device REMOVED` although the driver reports support (GPU thread off) | opening an `ID3D12PipelineLibrary` removes the device on this console | `pipeline_library=off` by default on UWP, `pipelines.d3d12.loading` crash marker; per-PSO cached blobs not shipped (untested) |
| run 9 (849) | **15-20 fps**, CPU-bound: draws 15-24 ms/frame, GPU wait 0, "rest" 30-41 ms (the guest's code) | Jaguar-class per-thread speed and per-draw rebinding | bind only what changed (`Context::bound`), `[perf]` render-thread split, **Series package `x86-64-v3`** |

Budget expectation (from [renderer_threads.md](../../runtime/gpu/renderer_threads.md)): the console's limit is the game's render thread (Zen 2 at 3.8 GHz, slower per thread than the M1 Pro); if its per-thread speed is 1.5-2.5x lower the render thread needs 30-50 ms in the 3700-draw part -> ~30 fps most of the level, 20-30 heaviest, **never measured with the GPU thread on**.

## Portals on Xbox (untested on a console) [Xbox]
Xbox One portal (`1430:09AB`, wired): a **GIP** accessory owned by the console's driver; the UWP route is `Windows.Gaming.Input.Custom` (`GameControllerFactoryManager.RegisterCustomFactoryForGipInterface` with the interface GUID `{1F7788A2-B860-9B40-3626-EC56C7C45256}`, `GipGameControllerProvider.SendMessage` as message `0x21` with a 30-byte payload, `IGipGameControllerInputSink.OnMessageReceived`; `GipMessageClass` `Command` first, then `LowLatency`, `StandardLatency`). HID portals (1430:0150): `Windows.Devices.HumanInterfaceDevice` (manifest `humaninterfacedevice`, `vidpid:1430 0150`, `usage:ff00 *`) or a controller factory for the hardware id. **Xbox 360 portal (1430:1F17): impossible** (vendor-specific USB, no driver on the console, `Windows.Devices.Usb` only reaches WinUSB devices, never HID class 03). `host/uwp/portal_backends.cpp` tries every route at once (worker rescans every 2 s; waits up to 4 s at start); `[portal] mode` auto/real/emulated; the Toy Box (View + Y, hold View = wheel) and the glyph sets (`xbox360`, `xboxone` = Menu as three lines) work on the console (`imgui_software.cpp` rasterises ImGui on the CPU into the 1280x720 overlay; the pad stays deaf after closing if stick dead zones are missing: sticks past 8000, triggers past 30 count as held). Portal diagnostics use `[portal]`: device visibility, access failures, `connected: <transport>` and
`disconnected: <transport>`. Only the first eight reports each way are logged unless `SKY_PORTAL_LOG=1`.
