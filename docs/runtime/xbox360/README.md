# Xbox 360 runtime: what the console did, what our runtime does instead

> **Purpose:** what does the title expect from the console (kernel, XAM, memory, files, audio, video, input), and how does our hand-written runtime answer it? · **Status:** current (2026-10-26) · **Tags:** [Xbox] [XDK]

Class tags used in this folder: **[Xbox]** Xbox 360 generic (carries over to every game), **[XDK]** the development
kit's libraries linked into the title, **[Lux]** / **[Alchemy]** an engine's use of it, **[SSA]** / **[Giants]** one
binary (re-find for another game). **[V]** verified, **[?]** a lead.

## What it is

- **Recompiled code** (`private/<id>/ppc/`, generated by XenonRecomp from the player's `default.xex`, never edited,
  never committed) plus this runtime. Generated functions are weak; a strong `PPC_FUNC(sub_X)` overrides one.
- **Layers** `runtime/{kernel,d3d,gpu,apu,host,platform}`: `kernel/` answers the imports; `d3d/` hooks the title's
  statically linked D3D9LTCG and rebuilds each draw, resolve, clear and swap from the device state; `gpu/` is the host
  renderer on plume; `apu/` the XMA decoder; `host/` SDL3 (and UWP), portal, figures, collection, Toy Box, settings, the
  `--launcher` window; `platform/` POSIX and Win32.
- **Title-independent, with one door.** The runtime never names a game's address: a hook is written
  `PPC_FUNC(GAME_HOOK(Name))` inside `#ifdef GAME_HOOK_Name` (`runtime/game_hooks.h`), and each game's
  `games/<id>/addresses.h` defines the names it has (and the data globals in `namespace game`). Per-game behaviour that
  is not an address goes through the adapter (`runtime/game.h`, filled in `games/<id>/adapter.cpp` and
  `games/<id>/info.cpp`). Engine code lives in `engines/<engine>/`, game-only code in `games/<id>/`. Detail:
  [architecture/hooks.md](../../architecture/hooks.md), [architecture/layout.md](../../architecture/layout.md).
- **Threads**: the host main thread owns the window and input; the title runs on guest threads (16 MB host stacks,
  `runtime/thread.cpp`); a graphics interrupt thread, an audio driver thread, the portal I/O thread (`AsyncPortal`), the
  GPU thread and texture threads.
- **Exit** is `std::_Exit(0)` (`runtime/main.cpp`: no static destructors under live threads).

### The numbers [Xbox]

| Area | Fact | Code |
|---|---|---|
| Imports | 251 in `import_list.inc` (SSA 218 + Giants 33): 174 implemented, 77 weak stubs that log `[stub] Name` once and return 0; ordinals `0x4A1/0x4A2` (portal) served by host thunks | `runtime/kernel/` |
| Kernel traps | `KeTimeStampBundle` ticks every 1 ms; `Ke*` objects bound through the `'SSAK'` marker in the dispatcher header (inlined initializers overwrite headers); real `PulseEvent`; user APCs for `ReadFileEx`; zero-count waits fail; back-off after 32 fast yields (200 us sleeps); critical sections in guest memory with the KTHREAD as big-endian owner; fences for `lwsync/sync/eieio` | `kernel/objects.cpp`, `kernel/threads.cpp`, `kernel/sync.cpp`; fences: `patches/xenonrecomp.patch` |
| XAM | offline XNet (`XNET_GET_XNADDR_NONE`), XConfig (NA retail, HD), XMP (title has control, system 2.0.17559.0), one offline profile (XUID `0xE000000000000001`), achievements accepted, empty enumerator | `kernel/xam*.cpp`, `kernel/xmp.cpp` |
| Memory | 4 GB guest block (`base + address`); 4 KB heap `0x10000..0x40000000`; 64 KB heap `0x40000000..0x70000000`; system bump heap `0x70000000..0x80000000`; 512 MB physical through the windows `0xA0000000` (64 KB pages), `0xC0000000` (16 MB), `0xE0000000` (4 KB, **+0x1000**), which do not alias (each allocation remembers its window); Windows commits 64 KB on fault when 4 GB cannot be committed | `runtime/memory.cpp`, `kernel/memory.cpp` |
| Files | XDVDFS layouts at `0x0, 0x2080000, 0xFD90000, 0x18300000`; saves are content packages `<save root>/<type>/<name>` | `runtime/vfs.cpp`, `kernel/files.cpp`, `kernel/xam_content.cpp` |
| Video | **Option B**: replace the title's D3D9LTCG functions, translate to plume (Metal, Vulkan, D3D12), no PM4 execution except the ring mirror; guest depth reversed; present interval 2 on a 60 Hz emulated vblank (30 fps), `--fps-limit 60` shows every vblank; null-GPU fences retire when kicked off | `runtime/d3d/`, `kernel/video.cpp` |
| Audio | XAudio2 render driver: one thread, 256 samples at 48 kHz, 6 planar channels, SDL3 out (XAudio2 2.9 on UWP); XMA through a static LGPL wmapro-only FFmpeg, frame by frame; XMA register file at `0x7FEA0000` with hooked writers; Bink frames through the same renderer | `kernel/audio.cpp`, `kernel/xma.cpp`, `runtime/apu/` |
| Input | XAM input for user 0 only; SDL3 gamepad and keyboard (Windows.Gaming.Input on UWP); glyph textures replaced by content hash | `kernel/input.cpp`, `host/input.cpp`, `host/glyphs.cpp` |

**A stub that returns success without writing its outputs is the classic trap**: grep `[stub]` per screen
([stubs.md](stubs.md)).

## Where the code is

`runtime/kernel/` (imports; `import_list.inc`, `stubs.cpp` makes the weak stubs, `imports_giants.cpp`),
`runtime/loader.cpp` (XEX), `runtime/memory.cpp`, `runtime/thread.cpp`, `runtime/vfs.cpp`, `runtime/apu/`,
`runtime/host/` (SDL3, input, audio out), `runtime/host/uwp/`, `runtime/platform/` (`platform_posix.cpp`, `platform_win32.cpp`). The code folder's
README: [runtime/README.md](../../../runtime/README.md).

## How to test it

`tools/test_all.sh` (both games, [testing.md](../../getting-started/testing.md)); a short isolated run and a grep of
`[stub]` and `[kernel]` lines in the log. Adding a game: diff its XEX imports against `import_list.inc`
(`tools/day1.sh` does it) and implement each missing one *with its outputs written*.

## Gotchas

- A stub that "succeeds" without its outputs ([stubs.md](stubs.md)); the same 77 stubs were checked harmless for SSA
  only.
- The `0xE0000000` window has the +0x1000 offset ([memory.md](memory.md)).
- Every cause and fix: [gotchas.md](../../porting/gotchas.md) (D1-D44) and
  [problem_catalogue.md](../../porting/problem_catalogue.md). The Xbox Series X console runs and their fixes:
  [Xbox UWP](../../getting-started/platforms/xbox_uwp.md).
