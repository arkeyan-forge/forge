# GX textures decoded on the host

> **Purpose:** the Wii's texture formats decoded to linear RGBA8, without a GPU or game data · **Status:** current (2026-11-25) · **Tags:** none

[`runtime/wii/gx_texture.h`](../../../runtime/wii/gx_texture.h) exposes `wii::gx::EncodedSize` and `wii::gx::Decode`.
The decoder reads bytes directly, with big-endian 16-bit words, and writes R, G, B, A bytes in row-major order,
top row first. It allocates no memory. Source, palette and output buffers must not overlap.

## Tiles and sizes

Tiles run left to right, then top to bottom. Pixels within a tile follow rows, except for RGBA8's two planes and
CMPR's four sub-blocks. Edge tiles occupy their full encoded size; pixels beyond the image's width or height are
dropped. `EncodedSize` rounds both dimensions up to whole tiles for one mip level.

| Format | Value | Tile | Bytes per tile | Pixel representation |
|---|---|---|---|---|
| I4 | 0 | 8×8 | 32 | High nibble first; intensity fills R, G, B and A |
| I8 | 1 | 8×4 | 32 | Intensity fills R, G, B and A |
| IA4 | 2 | 8×4 | 32 | High nibble alpha, low nibble intensity |
| IA8 | 3 | 4×4 | 32 | Alpha byte, then intensity byte |
| RGB565 | 4 | 4×4 | 32 | Big-endian RGB565, opaque |
| RGB5A3 | 5 | 4×4 | 32 | Big-endian RGB555 or A3RGB444 |
| RGBA8 | 6 | 4×4 | 64 | 32 bytes of A,R pairs, then 32 bytes of G,B pairs |
| C4 | 8 | 8×8 | 32 | 4-bit palette index, high nibble first |
| C8 | 9 | 8×4 | 32 | 8-bit palette index |
| C14X2 | 10 | 4×4 | 32 | Big-endian index, upper two bits ignored |
| CMPR | 14 | 8×8 | 32 | Four compressed 4×4 sub-blocks |

## Colour expansion and palettes

Small components expand by bit replication: 3 bits become `(v << 5) | (v << 2) | (v >> 1)`, 4 bits become
`(v << 4) | v`, 5 bits become `(v << 3) | (v >> 2)` and 6 bits become `(v << 2) | (v >> 4)`.
RGB5A3 with bit 15 set holds opaque RGB555. With bit 15 clear, bits 14–12 hold alpha, followed by RGB444.

C4, C8 and C14X2 use a caller-provided palette of `tlutEntries` big-endian 16-bit entries. `TlutFormat` selects
IA8 (0), RGB565 (1) or RGB5A3 (2), using the same colour rules as direct textures. An index at or beyond
`tlutEntries` produces transparent black. A non-null palette with zero entries produces only transparent black.
Padding pixels in partial tiles never require a palette lookup.

## CMPR

Each tile holds its top-left, top-right, bottom-left and bottom-right 4×4 sub-blocks in that order. A sub-block
has two big-endian RGB565 endpoints `c0`, `c1`, then four bytes of indices, one per row. The leftmost pixel uses
the highest two bits. Endpoint ordering compares the encoded 16-bit words.

When `c0 > c1`, the other colours are `(2*c0 + c1)/3` and `(c0 + 2*c1)/3`, opaque. Otherwise the third colour is
`(c0 + c1)/2` and the fourth is transparent black. Interpolation uses expanded RGB channels and integer division
with truncation; there is no interpolation of alpha.

## Errors and buffer requirements

The output buffer must hold `width * height * 4` bytes, and the palette must hold `tlutEntries * 2` bytes.
`Decode` returns false without modifying the output for an unknown texture format, a short source, a missing
palette on an indexed texture, an unknown palette format on an indexed texture, null nonempty buffers, or a size
that cannot be represented. `EncodedSize` returns zero for unknown formats, empty levels, or encoded sizes
exceeding `uint32_t`. Empty levels with valid format and palette arguments decode successfully without buffer
access. Input and output lengths are checked for representability before decoding.

## Test

From the checkout's root, with the tests-only build configured:

```sh
nice ninja -C build-tests -j4 ArkeyanGxTextureTest ArkeyanWiiTest
nice ./build-tests/ArkeyanRuntime/ArkeyanGxTextureTest
nice ./build-tests/ArkeyanRuntime/ArkeyanWiiTest .scratch/wii
python3 -I tools/check_docs.py
```

`ArkeyanGxTextureTest` is also registered with `ctest`. It builds and encodes synthetic pictures for every format
at 13×7, 1×1, 8×4 and 33×17, decodes them and compares every output pixel with the original picture. Known byte
cases check component expansion, byte and bit order, palette formats and CMPR interpolation, including equal
endpoints. Error cases check that refused inputs leave the output untouched, and guards check edge writes.
The test reports a 1024×1024 CMPR decode's duration; Release builds require less than 50 ms. Its final line reports
the check and failure counts, with exit status 1 for any failure. All pictures are generated by the test itself.
